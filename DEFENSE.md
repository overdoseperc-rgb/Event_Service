# Текст для защиты

Я выбрал авторскую тему «Сервис управления мероприятиями». Она не повторяет темы других студентов и подходит для дальнейших практик по Linux, Docker, Docker Compose и архитектуре.

В репозитории я создал `README.md`, заметки по проекту, план API и рабочий прототип на Python. Прототип умеет создавать мероприятия, показывать их список и регистрировать участников.

Для раздельной работы я создал ветки `feature/api-details`, `docs/project-goals` и `feature/project-description`. В первой ветке уточнил формат API, во второй описал цель проекта, а в третьей изменил описание сервиса. Готовые изменения объединил с `main` через merge-коммиты.

Конфликт возник в `README.md`, потому что ветка `main` и ветка `feature/project-description` изменили одну строку по-разному. Git показал конфликтные маркеры. Я вручную составил итоговую формулировку, удалил маркеры и создал коммит `fix: resolve README merge conflict`.

По графу веток видно, где ветки отделялись от основной истории и где возвращались в `main`. В истории больше шести осмысленных коммитов, три рабочие ветки, обычные merge-коммиты и merge-коммит с разрешённым конфликтом.
